# Make your GitHub profile showcase engineering experience

GitHub displays a special README **directly at the top of your user profile** when a **public repository with exactly the same name as your username** exists. For this account the repository must be named **`sopskistar`** (owner `sopskistar`). The separate engineering evidence hub already exists at [sopski-Lab](https://github.com/sopskistar/sopski-Lab); it will remain your technical log.

## Setup (GitHub website)

1. Visit [Create repository](https://github.com/new) while signed in.
2. Select the owner **sopskistar** and repository name **sopskistar** (exact same spelling and capitalization).
3. Select **Public** and enable **Add a README file**.
4. Create the repository. GitHub recognizes it as your profile README.
5. Open [PROFILE_README_TO_COPY.md](../PROFILE_README_TO_COPY.md) in this Lab, copy its full text, and paste into the new repo's `README.md`. Commit the change.
6. Open [github.com/sopskistar](https://github.com/sopskistar) and review desktop and mobile rendering.
7. Optionally pin the strongest evidence-backed repositories through GitHub's **Customize your pins** UI. Recommended: Flownix, LeadAtlas, ReturnTail, RouteTill, Cuelira, and sopski-Lab.

**Why a separate Lab and a profile README?** The profile is a short recruiter-facing introduction. The Lab is where you accumulate hard evidence, diagrams, incidents and new capabilities. Each application README is the project-specific technical proof.

**Careful:** Creating a public profile README does not expose private repository contents, but anything included in the README is public. Never paste secrets, private emails or unredacted deployment variables.
